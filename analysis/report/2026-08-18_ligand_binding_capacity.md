# 配体结合能力验证：条件化改造是否破坏 LigandMPNN 的配体结合设计

> 日期：2026-08-18　用途：回答"维持 LigandMPNN 的配体结合能力"——验证冻结 backbone + 条件旁路注入的改造是否损害模型原生的配体结合位点设计能力。
> 数据：2 个配体复合物（1FQG = 单链 HIV-1 蛋白酶 + PNM；3T0F = 双链蛋白酶 + F3S/H6P），每组 n=20，三对照。

---

## 一、结论先行

1. **配体结合设计功能完全可用**：原版 LigandMPNN 权重（含配体上下文）+ v7 条件编码器组合跑通，配体被正确感知（Pocket 定位准确）。
2. **但条件化有一个已量化的代价**：生成时**结合位点 recovery 下降**（1FQG 0.62→0.41、3T0F 0.71→0.58）——条件注入的全局改写会波及配体口袋。
3. **缓解方案已验证有效**：**固定结合位点残基 + 条件化** 完全兼容（电荷命中 dev 0.79、结合位点 100% 保持）——**做配体结合设计时固定口袋残基即可同时获得"电荷控制 + 配体能力"**。
4. **新增限制**：条件化在**大蛋白（L>400）/多链**上电荷失配（3T0F 双链 L=618 dev 21）——训练数据全是 CATH 单体域（L<400），条件向量与骨架规模的组合失配。

---

## 二、架构论证（为什么配体能力理论上保留）

- 条件化 = **冻结 backbone + cross-attention 旁路注入**（`h_V += softmax(h_V·promptᵀ/√d)·prompt`，`conditioned_sampler.py`）。
- 配体信息由 backbone 编码进 `h_V`（原版 LigandMPNN 的 LigandMessagePassing 处理配体原子上下文）；条件注入是**加性旁路**，不覆盖、不修改配体上下文。
- 因此配体感知与条件注入**在同一 h_V 上共存**——这是架构上"能力保留"的依据。
- **冒烟验证**：LigandMPNN 权重 + v7 编码器在配体模式跑通，token_dim 匹配（128），条件注入正常。

---

## 四、分析

### 4.1 结合位点 recovery 下降（0.62→0.41 / 0.71→0.58）

- 机制：条件化编码器学的是"全局改写以满足电荷目标"，在配体复合物上应用时**连口袋残基一起改写**，部分抵消了原始 LigandMPNN 在配体附近的保守性（recovery 高）。
- 幅度：单链蛋白口袋小（8 残基）时降幅大（0.21）；双链口袋大（32 残基）时降幅小（0.12）——**口袋越大越稳健**。
- 注意：recovery 下降 ≠ 结合失效。设计序列可能用不同残基仍维持与配体的互补（recovery 只是"保持 native"的代理）。但这是**需要诚实报告的能力权衡**，且固定口袋可以完全规避。

### 4.2 3T0F 电荷失配（dev 21）

- 3T0F 双链 L=618、native −15.2。条件向量在训练分布内（−15.2 约 1.5σ），但**生成严重过冲**（−36.5）。
- 可能原因：① 训练数据全为单体域（L<400 居多），618 残基的 h_V 规模超出条件编码器所见；② 双链输入的 chain_mask=全 1 合并处理与训练假设一致，但骨架规模超范围；③ native −15.2 在训练覆盖边缘（<2%）。
- **结论**：条件化的电荷控制可靠范围还需限制蛋白规模（L≤~300）与链数（单体）。

## 五、使用建议

| 场景 | 做法 |
|------|------|
| 设计配体结合位点序列（目标 2）| **固定结合位点残基**（`--fixed_residues`），条件化控制口袋外区域——已验证兼容 |
| 需要口袋内也设计 | 用**原始 LigandMPNN**（`--weights ligandmpnn_v_32_010_25.pt`，不加载 cond_encoder）获得最大配体保守性 |
| 单体小/中蛋白（L≤300）配体复合物 | 条件化可用，注意结合位点 recovery 会降 ~0.12-0.21 |
| 大蛋白（L>400）/多链 | **条件化电荷控制失配**，避免或先用单体域验证 |

## 六、与限制文档的关系
