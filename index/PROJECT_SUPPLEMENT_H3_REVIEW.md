## 1. H3 电荷聚集合法性 — 执行方案

### 1.1 H3 判据（DESIGN_CRITERIA.md 原文）

> 条件臂序列在结构过滤器规则下**违规率 ≤ 基线违规率 + 5 个百分点**；任何设计不得产生物理上不可能的电荷布局。

### 1.2 关键区别：采样时过滤器 ≠ 事后裁判

- 现有 `code/src/structure_aware_filter.py` 的 `StructureAwareFilter` 是**解码时引导**：对违反规则的下一未解码位置施加负 bias（抑制继续放同号电荷），防"生成过程中堆积"。
- H3 判据是**事后对最终序列计数**——需要一个**新的事后评估脚本**，复用现有 4 条规则，但改成"全序列已解码、只统计不干预"模式。

### 1.3 规则口径（直接用现有代码，零新增规则）

| 规则 | 判定 | 阈值（CATH S40 p99） |
|---|---|---|
| charge_cluster | 10Å 内同号电荷 ≥6 → 该位置违规 | p99=6 |
| salt_bridge | 10Å 内正负电荷对 ≥4 → 违规 | p99=4 |
| core_charge | 埋藏位置（10Å 邻居数居前）8Å 内带电 ≥6 → 违规 | p99=6 |
| same_sign_cluster | 8Å 连通图同号 ≥4 → 违规 | p99=4 |

### 1.4 新脚本 `code/tests/h3_charge_legality.py`（建议）

- **输入**：
  - 条件臂：泛化 10 蛋白 × 5 臂 × n30 生成 PDB（`output/generalization_v12_2_calib/`，small 口径）
  - 基线①：`native_ref`（原始 PDB 经 parse_PDB 提取，与采样同序列空间）
  - 基线②：无条件基线（`output/tm_sol_v12_2/uncond/`，**必须用训练均值占位 net_charge=1.4243**，`net_charge=None` 会 poly-G 退化）
- **方法**：
  - 坐标：直接用采样用的骨干 PDB（与生成同构），Cα 距离矩阵
  - 逐条规则统计"触发位置数 / 总长"；聚合违规位置 = **4 条规则的并集去重**（一个位置可能同时触发多条，去重防止高估）
  - **按 pH 分臂统计**：调用 `pH_adaptive_charged_aa(pH)`（His pKa6.0 / Cys 8.3 / Tyr 10.1 在不同 pH 判电）
  - 输出：每蛋白每臂违规率表 + 三组对比（条件臂 / native_ref / 无条件基线）+ 每条规则的 info 计数
- **判据**：主判据照抄 `条件臂违规率 ≤ max(native, 无条件) + 5pp` → PASS

### 1.5 判据口径提醒（先取证、后定标）

- 过滤器阈值是 CATH 的 **p99**，native 蛋白本身基本不触发（违规率≈0）→ "≤0+5pp" 是**相当严格**的口径：条件臂任何一臂 >5% 位置触发即 FAIL。
- `DESIGN_CRITERIA.md` 末尾自己注明"阈值可依据实际数据讨论调整"。**先跑出基线真实值再锁判据，不要预设结论**。
- 若极端 pH 臂（n8/p8）系统性超 5%，本身就是值得写进论文的**失败分析**，不是要藏的问题。

### 1.6 H3 的额外价值（方法学副产物）

v12.2 泛化采样时 `run_guided.py` Phase 1 本来就走 `structure_filter` bias 引导（`--preset` 默认加载）——H3 事后统计可顺带回答"**第 3 条规则的引导是否真的约束住最终序列**"。若事后违规率高，说明 `--strength` 不足，可反推调整。这写进论文控制流程部分。

### 1.7 为什么 H3 不能省

H3 是四大硬判据唯一空置的，且是"电荷斑块/聚集可学习"卖点最直接的科学性证据（证明生成物符合生物物理电荷规律、没有堆出不可能的同号电荷团）。审稿人看到 H3 空置会直接质疑"电荷条件化是否产生物理上不可能的序列"。

## 2. 校准机制存疑点复核（用户 9 问 → 结论）

> 全部基于真实代码（`build_calibration*.py` / `v10_diag_response_curve.py` / `validate_holdout.py` / `v12_losses.py`），非印象回答。

### 2.1 响应公式与 slope（A1）

```
生成电荷均值 ≈ slope × target + intercept   （每蛋白 target 网格 11 点 × n=20，最小二乘）
target_eff   = (desired − intercept) / slope  （校准反函数，喂给条件向量电荷维）
```
- **可信度**：点都是真实采样 + HH 电荷计算；r²≈0.98–1.00 说明**网格覆盖区间内**线性近似好；**区间外推与弯曲段不保证**（1A65/1BJ4 的根因）。

### 2.2 三张表真实来源（A2）

| 表 | 脚本 | 来源 | 点数 | 是否训练域 |
|---|---|---|---|---|
| 诊断表 | `build_calibration.py` | 17 验证蛋白 | 187+ | ❌ |
| big 表 | `build_calibration_big.py` | **92 训练域**分层抽样 | 460 | ✅ 是 |
| small 表 | `build_calibration_small.py` | 目标蛋白现场 5t×n10 | 50/蛋白 | ❌ 当下采样 |

- 调用时机（`--calibrate auto`）：表内→per-protein；表外→回退 global；unreliable→回退 global。

### 2.3 "训练域进表=作弊?"与边界（A3）

- 表只在"目标蛋白恰好在 per_protein"时有用；表外一律走 global 或现场标定。用训练域拟合 global 反而是**最保守**口径（44%）。
- **训练改"响应规律"、表只记录"当前模型的指纹"，两者正交不可替代**：v12.1 slope 1.748→v12.2 1.579 是 λ_target 在训练侧改的，不是校准。
- **边界**：交付物 = 模型 + 校准协议。表内 per-protein（72%）/ 表外现场 50 条标定（74%）/ 不标定 global（40–44%）。论文必须写清楚这条边界。
- **补充建议**：补一个"**未训练基线（无条件微调）标定失效**"对照实验——证明校准是叠加在训练之上的适配。若未训练模型对其标定后命中率≈0，边界问题就从薄弱点变成卖点。

### 2.4 命中率统计口径（A4）

- 主判据：简化 HH（可微、快、与训练同尺）；PROPKA 只做 H4 抽样复核（物理一致性副证）。
- v12.1 已实测 Q_design≈Q_phys（dev<1.5），无需每轮重算 PROPKA，但论文应放一张 Q_design vs Q_phys 一致性图。

### 2.5 响应弯曲 + LOOCV（A5）

- 小样本 5 点横跨弯曲段 → 拟合出"割线"；命中与否取决于 target_eff 落在直线≈曲线或直线≠曲线的段。
- n20 治均值噪声、治不了弯曲；n10 噪声有时碰巧补偿弯曲（1BJ4：n10 slope 3.007 却 5/5，n20 slope 2.747 反而 2/5）。
- LOOCV 检测"拟合被个别点主导"→ 标 unreliable（>3.0）→ 回退 global。**多采样 ≠ 治弯曲，LOOCV+回退才是诚实应对**。

### 2.6 n10=50 条（A6）

`OFFSETS=[-8,-4,0,4,8]` × `n_per=10` = 50 条/蛋白，5 个 (target, mean_charge) 点拟合。

### 2.7 1BJ4 组成 0.59×（A7）

- **非直接命令删残基**：1BJ4 native 净电荷≈0 → λ_target 锚定表面净电荷为小绝对值 → 模型发现"两边都删（总量 105→62）"比"正负守恒"更容易满足 frac_floor=0.5 + GRAVY margin 0.4。
- 规律：|target| 小 → 删减凑数路径；|target| 大 → 过量添加（1A65 1.45×）。
- **改进选项**：① 组成监督加上界（count ≤ native×1.2）；② 双向"贴 native"软约束；③ λ_target 仅 target 明显偏离 native（±8）时激活。

### 2.8 "17 表太小 / big92 更真实 / 40→44 提升"（B8）

- **17 表**：作为 per-protein 查表对论文 fixed set 够用（10 valid 全覆盖）；作为 global 兜底代表性确实弱。
- **big92**：更接近"模型真实平均响应"、统计更稳、是干净无泄露口径——**建议设为 `run_guided.py` 默认 global 兜底**（由用户决定是否执行）。
- **40.6% vs 44% 不可比**（关键纠正）：
  - 40.6% = 17 表 global → **28 个 CATH 训练域**（hold-out，`force_global=True`，28域×8pH×n5=224 样本）
  - 44% = 92 表 global → **10 个 valid 蛋白**（10×5臂×n30）
  - **测试集 + 协议均不同**，无法归因"扩表带来 3.4pp"。报告里"big92≈hold-out → 固有局限坐实"的写法证据不足。
  - **必须补同测试集对照**：valid 10 蛋白分别用 17 表 global 与 big92 global 跑（n30），逐臂输出命中率对比。

### 2.9 "训练集和验证集分别有校准表吗"（B9）

- **不是**。一个 JSON 里同时含 `global` + `per_protein`，运行时按目标蛋白名是否命中 per_protein 选择。
- 真实区别是"表来源"：诊断表（17 验证蛋白）/ big 表（92 训练域，主要贡献 global）/ small 表（目标蛋白现场）。big 表虽也存 92 域 per_protein，但评估时不会命中，只走它的 global。
